# ترازبان

پایش پیوستهٔ ریسک چرخهٔ خرید تا پرداخت.

حسابرسی معمولاً ماه‌ها بعد از پرداخت و روی چند نمونه انجام می‌شود، و ریسک همیشه در نمونه نمی‌افتد. ترازبان همهٔ سندهای خرید تا پرداخت را بررسی می‌کند و برای هر هشدار نشان می‌دهد چه چیزی غیرعادی است و شواهدش در کدام فایل و کدام سطر است.

![پروندهٔ یک هشدار](docs/case.jpg)

## وضعیت فعلی

این مخزن نمونهٔ اولیه است.

**روی فایل واقعی اجرا می‌شود** (صفحهٔ شروع یا صفحهٔ «داده»، بارگذاری CSV):

- یکسان‌سازی حروف و ارقام فارسی و عربی
- فاکتور بدون سفارش خرید
- فاکتور تکراری یا مشابه: همان تأمین‌کننده، همان مبلغ، شمارهٔ فاکتور مشابه
- شکستن سفارش: چند سفارش زیر سقف تأیید که جمعشان از سقف بیشتر است
- انحراف قیمت خرید
- گزارش کیفیت دادهٔ همان فایل
- زنجیرهٔ شواهد هر هشدار تا نام فایل و شمارهٔ سطر
- ثبت تصمیم حسابرس روی هر هشدار (فعلاً فقط تا وقتی صفحه باز است)

**صفحه‌اش آماده است، با دادهٔ نمونهٔ ساختگی:** ریسک تأمین‌کننده، سقف اختیار تأیید، و تأیید انسانی برای یکی کردن تأمین‌کننده‌های هم‌نام. دادهٔ نمونه از دکمهٔ «دیدن با دادهٔ نمونه» یا نشانی `#/sample` باز می‌شود.

**هنوز ساخته نشده:**

- لایهٔ یادگیری رفتار عادی هر تأمین‌کننده، کاربر و واحد
- اتصال مستقیم به نرم‌افزار حسابداری
- سنجش دقت روی دادهٔ واقعی

### بررسی‌ها روی فایل واقعی چطور کار می‌کنند

- **خواندن فایل:** CSV با فیلدهای داخل گیومه، جداکنندهٔ `,` یا `;` یا تب، ارقام فارسی و عربی، جداکنندهٔ هزارگان (`,` `٬`)، اعشار سپیدار (`155000000/00`) و `٫`. خانه‌ای که عدد یا تاریخ معتبر نیست «نامعتبر» شمرده و در گزارش کیفیت داده نشان داده می‌شود، نه صفر.
- **فاکتور تکراری:** همان تأمین‌کننده، و یکی از این سه: شمارهٔ یکسان با شکل نوشتن متفاوت (مبلغ تا ۱٪ فرق)، شمارهٔ دوم همان اولی با پسوند (`F-100-A`)، یا دو رقم کنار هم جابه‌جا. دو حالت آخر فقط با مبلغ برابر و تاریخ‌های حداکثر ۳۰ روز فاصله.
- **فاکتور بدون سفارش:** فقط وقتی فایل ستون `po_id` دارد.
- **شکستن سفارش:** همان تأمین‌کننده و همان تأییدکننده، سفارش‌هایی در بازهٔ ۳ روز که هر کدام زیر سقف تأیید همان فایل است و جمعشان بیشتر از سقف.
- **انحراف قیمت:** قیمت واحد بیش از ۴۵٪ بالاتر از میانهٔ ۳ تا ۶ خرید قبلی همان کالا و واحد در همان فایل. تورم تدریجی هشدار نمی‌دهد.
- **شدت ریسک** از قدرت نشانه ساخته می‌شود (نزدیکی به سقف، اندازهٔ جهش قیمت، نوع شباهت شماره)، نه عدد ثابت.

آزمون موتور: `npm run check:engine`. صد هزار سطر حدود ۱.۵ ثانیه طول می‌کشد.

### هنوز نیست

- تطبیق بین فایل‌ها (فاکتور با سفارش و رسید انبار)؛ هر فایل جدا بررسی می‌شود.
- خواندن مستقیم فایل اکسل (`.xlsx`) و نام ستون‌های فارسی؛ فعلاً ستون‌ها باید مثل قالب باشند.
- سقف اختیار، ریسک تأمین‌کننده و صورتحساب الکترونیکی روی فایل واقعی.
- ذخیرهٔ تصمیم‌های حسابرس بعد از بستن صفحه.

## اجرا

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید. برای دیدن با دادهٔ نمونه: `http://localhost:3000/#/sample`

| صفحه | کار |
|---|---|
| نمای کلی | مبلغ درگیر به تفکیک قاعده و انبار، هشدارهای بحرانی باز، گردش کار |
| هشدارها | فهرست به ترتیب شدت ریسک، با جست‌وجو و فیلتر |
| پرونده | دلیل‌ها، زنجیرهٔ سندها تا سطر منبع، ثبت تصمیم و سابقه |
| داده | بارگذاری، قالب فایل‌ها، کیفیت داده، تأمین‌کننده‌های مشابه |

![نمای کلی](docs/overview.jpg)

## قالب فایل‌های CSV

فاکتورها:

```
invoice_id,invoice_number,po_id,supplier_id,supplier_name,invoice_date,total_amount,warehouse_code
```

سفارش‌های خرید:

```
po_id,supplier_id,supplier_name,item_code,unit,warehouse_code,quantity,unit_price,line_amount,po_date,approved_by,approval_limit_rials
```

مبلغ‌ها به ریال و تاریخ‌ها شمسی (`1404/11/14`) است. نمونهٔ هر فایل از همان صفحهٔ بارگذاری دانلود می‌شود.

## اصول

- امتیاز ریسک شدت نشانه است، نه احتمال تقلب. تصمیم نهایی با حسابرس است.
- دسترسی به داده فقط‌خواندنی است و هیچ تغییری در نرم‌افزار حسابداری داده نمی‌شود.
- شماره حساب‌ها پوشانده نمایش داده می‌شود.
